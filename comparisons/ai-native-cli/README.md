# AI-Native CLI — Presentation Engine Comparison

Independent implementations of the same 11-slide "AI-Native CLI: Give AI Its Own Manual" talk, each exercised through its native workflow rather than a shared theme/runtime.

- Source content (read-only, unmodified): `presentations\ai-native-cli\index.html`, `presentations\ai-native-cli\script.json`, `presentations\ai-native-cli\assets\*.png`
- 11 slides, in this order: Title → Help levels 1–3 (evidence) → Help levels 4–6 (evidence) → Accuracy vs relevance (comparison) → Syntax recovery (evidence) → List/Inspect (steps) → AI manual (4-card grid) → Build once (flow diagram) → Live demo (terminal) → Two front doors → Closing ask.
- English narration for every slide comes from `script.json`'s `say.primary` lines (grouped by the preceding `ask` tag, `SLIDE 1`…`SLIDE 11`).

No changes were made to `presentations\ai-native-cli\`. No git commits/pushes were made for this work.

```
comparisons\ai-native-cli\
├── frontend-slides\   Track A — hand-authored zero-dependency HTML/CSS/JS (oss-tools "frontend-slides" skill, Blue Professional template)
├── slidev\             Track B — official @slidev/cli project
├── revealjs\           Track C — official reveal.js npm package + Notes plugin
├── presenton\          Track D — official container, local Ollama, PDF/PPTX export
├── banana-slides\      Track E — official local UI; generation blocked on model authorization
└── pptagent\           Track F — official DeepPresenter CLI, local 9B model and sandbox
```

Each track has its own `metadata.json` (engine/version, verified features, presenter URL/shortcut, exports, known limitations) and its own `review\` folder with 1600×900 screenshots of all 11 slides plus feature-verification evidence screenshots.

## Track A — Frontend Slides (`frontend-slides\`)

Single self-contained HTML file generated by hand-following the `oss-tools/frontend-slides` skill (`SKILL.md`, `viewport-base.css`, `html-template.md`, `animation-patterns.md`), using the **Blue Professional** template from `bold-template-pack`. Fixed 1920×1080 stage scaled uniformly to the viewport (never reflowed), Space Grotesk + Inter type, single cobalt accent on a cream canvas.

**Files:** `index.html` (deck + inline CSS/JS), `assets\*.png` (copies of the 3 source screenshots), `verify.mjs` (Playwright screenshot/console/overflow check), `review\slide-01.png … slide-11.png`, `ai-native-cli-frontend-slides.pdf`, `metadata.json`.

**Commands run:**
```powershell
cd comparisons\ai-native-cli\frontend-slides
node verify.mjs                                          # screenshots (1600x900) + console-error + overflow check -> review\
& "C:\Program Files\Git\bin\bash.exe" -lc "cd '/c/Code/presentation-workbench/comparisons/ai-native-cli/frontend-slides' && bash '<frontend-slides skill path>/scripts/export-pdf.sh' index.html /c/Code/presentation-workbench/comparisons/ai-native-cli/frontend-slides/ai-native-cli-frontend-slides.pdf"
# NOTE: must pass an ABSOLUTE output path — the skill script has an upstream bug where a
# relative output path resolves inside its own temp dir and is deleted by its cleanup step.
```

**Verified:** fixed 1920×1080 stage w/ uniform scaling; keyboard (arrows/space/PgUp/PgDn/Home/End), mouse-wheel, and touch-swipe navigation; circular nav buttons with disabled edge states; staggered `.reveal` entrance animations; inline editing (hover hotzone + `E` key, JS-delay hover per the skill's guidance, not the broken CSS `~` approach) with `localStorage` autosave and an HTML export button; PDF export (11 pages, 1.1 MB) via the skill's own `export-pdf.sh`; zero console errors; zero overflow across all 11 slides.

**Not supported (by design of the skill, recorded in `metadata.json`):** presenter/speaker-notes mode. The `frontend-slides` skill has no notes/companion-window concept, so narration text was intentionally **not** faked into this deck.

## Track B — Slidev (`slidev\`)

Official `@slidev/cli` project (v52.18.0), scaffolded with `create-slidev`, own `package.json`/`package-lock.json`. Content in `slides.md`, English narration embedded per-slide as Slidev speaker notes (trailing Markdown HTML-comment blocks), source screenshots copied into `public\`.

**Commands run:**
```powershell
cd comparisons\ai-native-cli
npx create-slidev@latest slidev            # official scaffold (template: default)
cd slidev
npm install                                # @slidev/cli 52.18.0 + @slidev/theme-seriph
npm run build                              # -> dist\ with repository-aware Pages base
npm install -D playwright-chromium         # required by Slidev's own PDF exporter
npx slidev export --format pdf  --output slides-export.pdf    # 11 pages
npx slidev export --format pptx --output slides-export.pptx   # 11 slides (rasterized)
npx slidev --port 3040 --remote            # dev server + presenter route
```

**Outputs:** static site `slidev\dist\index.html`; PDF `slidev\slides-export.pdf` (11 pages, verified via `pdf-lib` page count); PPTX `slidev\slides-export.pptx` (11 slides, verified via zip `ppt/slides/slide*.xml` count); screenshots `slidev\review\slide-01.png … slide-11.png`; presenter capture `slidev\review\presenter-slide-01.png`.

**Presenter mode:** `http://localhost:<port>/presenter/<n>` (also toggled with the `p` key from the main deck view). Verified by loading the route in Playwright and confirming the notes pane renders the correct English narration for that slide (see screenshot above).

**Known limitation:** PPTX export rasterizes every slide as an image — text isn't editable in PowerPoint and speaker notes do not carry into the pptx notes pane (Slidev's documented behavior, not a bug here).

## Track C — reveal.js (`revealjs\`)

Official `reveal.js` npm package (v6.0.1) with the built-in **Notes** plugin. Native `.reveal > .slides > section` structure, own `package.json`/`package-lock.json`, one `<aside class="notes">` per slide holding the same English narration.

**Commands run:**
```powershell
cd comparisons\ai-native-cli\revealjs
npm init -y
npm install reveal.js                      # reveal.js@6.0.1
node scripts\serve.js                       # tiny static server, http://127.0.0.1:5178
node scripts\build-dist.js                  # -> dist\ (self-contained deployable copy, vendored reveal.js dist assets)
node scripts\verify.js                      # Playwright: screenshots, notes popup, overview, fullscreen, print-pdf
```

**Outputs:** deployable static site `revealjs\dist\` (own `index.html` + vendored `reveal.js` dist assets + images); print-to-PDF `revealjs\dist\ai-native-cli.pdf` (11 pages, verified via `/Type /Page` object count); screenshots `revealjs\review\slide-01.png … slide-11.png` (dev) and `revealjs\review-dist\*` (built copy); evidence screenshots `notes-popup.png`, `overview.png`, `help-overlay.png`.

**Verified presenter/UI features (reveal.js v6 default bindings):**
- **Speaker notes window** — press `S`; Playwright captured the real `window.open` popup ("Speaker View") and confirmed its DOM contains the current slide's English narration.
- **Overview** — press `O` (or `Esc`); confirmed `Reveal.isOverview() === true` and the `.reveal.overview` class.
- **Fullscreen** — press `F`; confirmed via the deck's own Keyboard Shortcuts help overlay (`?`) listing `F → Fullscreen`, and by intercepting the `requestFullscreen` call it triggers (headless Chromium cannot enter real OS fullscreen, so the API call itself is the verification point).
- **PDF print path** — `index.html?print-pdf` triggers reveal.js's print stylesheet; `page.pdf()` produced an 11-page PDF, page count verified programmatically.
- Zero console errors, zero layout overflow across all 11 slides, in both the dev copy and the built `dist\` copy.

## Cross-track final verification (this session)

Run once per track, from a clean checkout, in this order:

```powershell
# Track A
cd comparisons\ai-native-cli\frontend-slides
node verify.mjs

# Track B
cd comparisons\ai-native-cli\slidev
npm run build

# Track C
cd comparisons\ai-native-cli\revealjs
node scripts\build-dist.js
```

| Track | Slides | Console errors | Overflow | Static/deployable output | PDF | Presenter notes |
|---|---|---|---|---|---|---|
| frontend-slides | 11/11 | 0 | 0 | single-file `index.html` (+`assets\`) | ✅ 11 pages, 1.1 MB | ❌ not supported by the skill (documented) |
| slidev | 11/11 | 0 (1 harmless headless-only Wake Lock API warning) | 0 | `dist\` static site | ✅ 11 pages (PDF) + 11 slides (PPTX, rasterized) | ✅ `/presenter/<n>`, notes verified |
| revealjs | 11/11 | 0 | 0 | `dist\` static site (self-contained) | ✅ 11 pages (`?print-pdf`) | ✅ `S` key popup, notes verified |

**Real blockers encountered (all worked around, documented in each track's `metadata.json`):**
1. `frontend-slides` skill's `scripts/export-pdf.sh` silently loses the output PDF when given a *relative* output path (its own `cd "$TEMP_DIR"` + later `rm -rf "$TEMP_DIR"` deletes it before you can find it). Fixed by always passing an absolute output path.
2. Slidev's PDF exporter needs its own local `playwright-chromium` devDependency even though Playwright is already installed at the repo root — Slidev does not resolve browsers from an ancestor `node_modules`.
3. Headless Chromium cannot enter real OS-level fullscreen (no display/user gesture) — reveal.js's `F` fullscreen binding was verified by confirming it invokes `requestFullscreen()` on the deck root (the documented v6 behavior) rather than by observing an actual fullscreen transition.

The three browser-engine tracks remain self-contained sub-projects. Their built
static output is committed so GitHub Pages can publish the exact versions that
were reviewed. The root build only copies the selected comparison artifacts
into the Pages output; it does not replace any engine's native build pipeline.

## Track D — Presenton

The official `ghcr.io/presenton/presenton:latest` image was run locally with its
own bundled Ollama support and `gemma3:1b`. The workflow accepted the prompt,
text outline, and three screenshots, generated an outline, allowed all 11
Markdown blocks to be edited, rendered an Executive-template deck, exposed
per-slide speaker notes, and exported both PDF and PPTX.

The local 1B model repeatedly produced malformed outline JSON and later generated
unrelated template/example content even after the outline was manually corrected.
The output is retained because this is the real result of the tested offline
configuration, not a hand-corrected imitation. See `presenton/metadata.json`.

## Track E — Banana Slides

The official backend Dockerfile and frontend Vite app were built and run. The
hosted and local UI expose idea/outline/description generation, PPT renovation,
per-page templates, narration text, and presentation-video export. No real model
credentials were available. The official OpenAI OAuth route was initiated, but
the integrated browser hit Cloudflare 403 and no user was available to approve
account access in the system browser. No fake output was produced. See
`banana-slides/metadata.json`.
